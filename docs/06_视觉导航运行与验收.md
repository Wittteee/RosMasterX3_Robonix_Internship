# 视觉目标导航运行与验收

## 范围与状态

依据 2026-10-11 阶段汇报，第一阶段目标为指定二维码触发一次安全短距离导航，
不使用二维检测框估算米制距离，不接受视觉端任意坐标。默认推荐半径上限为 0.20 m。

2026-10-20 本机实现了完整软件流程和离线测试。以下实车事项不能由本机测试代替：
控制板有效应答、当前场地建图定位、相机标定、实际导航、取消后的物理停止及演示视频。
旧文档中的部署和故障信息是历史记录，不代表今天已确认的设备状态。

## 软件流程

`run_visual_nav.py` 调用 `VisualNavigation`，真实适配器是 `RobonixNavigation`。
参考接口核对版本为 safe_move `eabaec3e75463489481d98658f8918b82afb7c36`，
与仓库原部署记录相同。使用同一进程保持 Provider 的候选会话和一次性令牌。

1. 订阅 `/edition`、`/voltage`，10 秒内必须各收到有限正数，否则拒绝继续。
2. 实际打开相机读取图像，要求分辨率匹配标定，且指定内容的二维码恰有一个。
3. 以 `atan2(cx - center_x, fx) + camera_yaw` 计算方向，左正右负。
4. 官方 `preview_move_options` 检查定位、地图代价和路径；仅推荐方向匹配的服务端编号。
5. 重读图像并验证同一候选，调用 `prepare_selected_move`。
6. 默认在此结束，不执行。`--execute` 显示候选编号、距离和方向，要求输入“确认执行”。
7. 再检查底盘回读、目标和期限，调用 `execute_prepared_navigation`，不自动重试令牌。
8. 官方同步执行接口负责第三次校验、目标状态和导航看门狗。仅当 `ok`、`arrived`
   均为 true 且状态为 `SUCCEEDED` 时报告成功。异常、Ctrl+C 或未验证成功时请求官方取消。

运动期间由官方 Provider 监控导航，当前前端不持续追踪移动目标；它是一次目标触发任务，
不是持续跟随器。目标丢失检查覆盖准备前与确认后。相机卡死可能阻塞读取，执行前不会发送目标。
不要把此版本用于动态目标跟随。

取消接口返回的 `canceled` 仅表示取消消息已发送，本程序记录 `stop_verified=false`，
不会将其当成实车已停止。连接中断时取消也可能失败，现场必须有独立急停和看护。
本机上层不发布 `/cmd_vel`，也不调用硬件急停脚本去绕过此约束。

## 本机复现

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -X utf8 scripts\self_check.py
.\.venv\Scripts\python.exe -X utf8 scripts\preview_visual_target.py --demo
.\.venv\Scripts\python.exe -X utf8 scripts\run_visual_nav.py --demo
.\.venv\Scripts\python.exe -X utf8 scripts\run_visual_nav.py --demo --execute
```

最后一条需要人工输入“确认执行”。它仍然仅使用模拟 Provider。
二维码识别由 OpenCV 真实执行，但图像是生成的测试场景。
每次任务生成独立 `logs/vision/mission-*.json`，含模式、阶段、时间、候选和执行返回；
不记录可执行令牌。`physical_arrival_verified` 在模拟模式恒为 false。

## Jetson 部署与无运动检查

沿用 `docs/05_官方导航与目标检测接入.md` 中独立 Python 3.10 环境与已生成绑定，
不要替换系统 ROS Python。先把本仓库同步到 Jetson，再在它的根目录执行。
Windows 的 `.venv` 不可复制给 Linux 使用。

```bash
source ~/miniforge3/etc/profile.d/conda.sh
conda activate robonix
python -m pip install -r requirements-vision.txt
unset PYTHONHOME PYTHONPATH ROS_HOSTNAME
export ROS_MASTER_URI=http://127.0.0.1:11311
export ROS_IP=127.0.0.1
task_pkg="$HOME/rosmaster_x3_deploy/primitives/rosmaster_x3_bridge"
export PYTHONPATH="$task_pkg:$task_pkg/rosmaster_x3_bridge:$task_pkg/rbnx-build/codegen/robonix_mcp_types:$task_pkg/rbnx-build/codegen/proto_gen:$HOME/x3_rosbridge_adapter/scripts"
python -c 'import rosmaster_x3_bridge.main, rosmaster_x3_bridge_mcp'
```

ARM Jetson 若没有适配的 OpenCV wheel，需要在独立环境安装兼容的 OpenCV；
不能把系统 Python 的二进制扩展直接复制过来。安装结果需要在实际设备确认。

先在系统 ROS 环境运行 `scripts/jetson/check_chassis_health.py`，确认有效版本和电压；
再按厂商导航流程建立当前地图、初始化位姿，检查 `/scan`、`/odom`、TF、AMCL、
costmap、`/move_base/make_plan`。历史旧地图不能代替当前场地地图。
不要让 MakerControl 和 ROS 驱动同时占用底盘串口。

示例命令中的数值只展示格式，**须替换为实际标定结果**：

```bash
python scripts/run_visual_nav.py --camera 0 \
  --provider-dir "$HOME/rosmaster_x3_deploy/primitives/rosmaster_x3_bridge" \
  --label X3_TARGET_A --fx 500 --cx 320 --camera-yaw-deg 0 \
  --image-width 640 --image-height 480
```

此命令不执行移动，但会调用真实 Provider 预览和准备。只在当前地图、定位及实车前置条件
通过后，追加 `--execute`；人工审阅提示并确认。执行时按 Ctrl+C 会请求取消。
本机终端可通过 SSH 在 Jetson 运行，`--camera 0` 指运行脚本那台机器上的摄像头。
适配器在预览期间把官方候选搜索半径上限设为 `--max-radius`（实车支持 0.10–0.80 m），
默认 0.20 m；退出调用后恢复原环境变量，不修改参考 Provider 源码。
初次会话只允许一个导航客户端，避免其他任务共享全局取消接口。

## 实车验收记录表

以下项目当前均未在本轮实车验证。每次运行保留 JSON 和视频，不填写推测值。

| 项目 | 通过标准 | 记录内容 |
|---|---|---|
| 控制板 | 版本、电压有效；串口单一占用 | 板型、线缆、端口、回读 |
| 基础导航 | 当前地图、稳定定位、有效 TF 和规划 | 地图文件、初始位姿、基础导航结果 |
| 相机 | 实际帧可读，二维码唯一，方向符合左右约定 | 相机型号、标定、图像分辨率 |
| 预览 | 官方返回有效候选；未确认无运动 | 候选编号、角度、半径、日志 |
| 正常导航 | 确认后一次执行，真实 SUCCEEDED 与到点 | 日志、现场视频、位移 |
| 目标丢失 / 重复 | 准备前或确认后拒绝，未发送目标 | 画面和拒绝原因 |
| 无候选 / 健康失败 | 拒绝准备或执行 | 官方 reason 和回读 |
| 超期 | 人工确认过晚拒绝，无令牌重试 | 期限与时间戳 |
| 取消 / 异常停止 | 请求取消，现场确认实际停止 | 终态、停止延迟、视频 |
| 重复实验 | 每次新会话；分别统计成功与失败 | 试次、结果、失败原因 |

验收完成前，报告应写“软件离线流程通过，实车闭环待验收”，不能写“项目实车全部完成”。
