# 目标导航偏航与前进不足：日志分析

分析日期：2026-10-28。此轮只读取日志、配置和传感器，没有发送运动指令。

## 结论与证据强度

已确认导航到厂商底盘的速度映射存在额外衰减；短距离控制配置尚未与底盘可动速度和定位精度匹配。它们是当前首要问题。航向融合或电机响应不一致也值得检查，但现有汇总记录不足以唯一证明某个电机损坏、IMU轴向错误或角速度符号反转。

### 1. 线速度实际被驱动减半：确定

厂商 Mcnamu_driver.py 第143至149行将 vx=msg.linear.x*0.5、vy=msg.linear.y*0.8、angular=msg.angular.z*0.8 后传给 set_car_motion。
任务 DWA 最大前进速度为0.09m/s，角速度上限0.2rad/s，实际发到底盘最多为0.045m/s和0.16rad/s。
已现场确认可明显前进的直接底盘演示使用0.12m/s；导航的最大底盘前进指令仅为其37.5%。
此外任务将最小平移速度设为0，允许更低的采样指令。是否落入静摩擦/低速死区，仍需要测量，不应仅凭速度值直接判死。
我之前设定的0.09m/s规划上限没有同时核对该0.5增益，这是当前配置中的明确疏漏。

### 2. 补走阶段确实以较大的航向变化换来很小位移：确定

target_parking_resume.json：
- 导航活动约20.727秒，cmd_vel非零消息200条，最大线速度0.09、角速度0.2。
- odom位移0.1240m，累计路径0.1309m，平均路径速度约0.00632m/s。
- odom航向从-0.48965rad变为0.26647rad，净变化约43.32度。
- AMCL位移0.0884m，odom约为其1.40倍；两者并不等同于现场尺量距离。
- 用户现场反馈：肉眼基本看不到前进，主要看到航向变化。

这些数据支持优先检查低速响应、航向闭环、坐标变换和里程计标定。不能继续把日志中0.124m当作实物已经移动0.124m。

### 3. 2厘米到点要求尚未获得定位精度支持：确定配置，影响需要验证

任务把厂商默认的10厘米xy_goal_tolerance收紧到2厘米；局部地图分辨率为5厘米。
补走前AMCL最大位置方差为0.003216m²，标准差约5.67厘米，已大于2厘米到点门限。
最后AMCL点(0.28455,-0.02405)距实际下发候选点(0.30522,-0.00049)约3.13厘米，仍在2厘米门限外。
5厘米栅格不意味着技术上不能达到2厘米，但当前定位和底盘尚未标定，不应假定已具备该精度。

### 4. 首轮AMCL更新稀疏已确认，修复后仍失败

首轮执行期间AMCL观察消息数为0；厂商update_min_d为0.25m，与0.3m任务接近。
改为0.02m、update_min_a为0.03rad后，补走期间收到20条AMCL消息，但仍未成功到点。
因此定位更新频率是一个问题，但不是唯一原因。

### 5. “0个路径点”报错不能直接当作没有全局路径

两次执行前官方make_plan均成功，路径终点误差为0，候选点代价为0。
对照ROS Melodic源码：DWA在目标近于forward_point_distance时可关闭alignment评分；本机forward_point_distance为0.325m，大于初次0.3m路径和补走0.1m路径。
该评分项可能没有目标点，但评分器仍会执行prepare并输出空目标点错误，实际评分时又跳过权重为0的项。
因此该报错有可解释的非致命来源，不能单凭它认定全局路径丢失或障碍物堵死。尚未记录每个评分器状态，不能断言每一条报错都来自该分支。

### 6. 停车终态来自独立保护取消，而非到点：确定

两次终态均为PREEMPTED；外部guard明确记录time_limit，约20秒后请求取消。
Provider内部safety_watchdog_triggered=false。不要混淆外部guard与Provider内部保护，也不要写成导航完成或电机故障报警。

## 修复顺序

1. 统一导航和底盘的速度单位及增益；用可观察、可量测的短程验证最小可动速度。保持原安全速度限制，不直接调大速度或延长运行掩盖问题。
2. 在原地无运动与受控小角度实验中，同步记录cmd_vel、vel_raw、odom_raw、odom、imu和TF；验证正负方向、IMU安装变换和轮速标定。
3. 基于实测定位误差设置到点精度、最小平移速度和短距DWA参数；不能仅调大到点容差来宣称通过。
4. 再对同一地图停车点执行规划、到点和取消验证，验收以现场观察/测量及导航终态共同为准。

此次分析没有修改运动参数或再启动导航。
