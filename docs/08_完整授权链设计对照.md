# 完整授权链设计对照（2026-10-30）

按本轮用户完整需求实现，在原仓库增量完善，不修改车载导航栈。

## 第 5 节：安全状态机

实现：`src/x3_nav/safety/controller.py`。只依赖标准库。

- CandidateGoal 不可变，拒绝非有限坐标；预览必须给定同坐标系起点，使用 hypot 校验 ≤0.80 m。
- 每个控制器只有一个 session，不允许执行后重新预览复用；终态不可覆盖。
- prepare 只能从 PREVIEW 调用且 system_ok 必须为 True，使用 secrets 生成令牌。
- TTL 使用单调时钟；确认前和真正执行前均检查；执行立即清空令牌。
- snapshot 只返回 has_token，不返回令牌原文。FAILED 同样销毁令牌。
- 位移保护只允许 EXECUTING 阶段启用，阈值默认 0.080 m。

**需求歧义处理：** 状态序列包含 PREPARE→CONFIRM，同时要求 confirm 必须在 CONFIRM 中调用。
新增 `begin_confirmation()` 从 PREPARE 进入等待确认的 CONFIRM；随后 `confirm(token, human_ok)`
记录授权但不执行。`mark_executing()` 独立消费令牌。无 dispatch 时保留 CONFIRM，绝不假记 EXECUTING。
等待确认期间失败只能结束为 FAILED，不能从终态返回准备阶段。

测试：`test_safety_state_machine.py`、`test_mission_dry_run.py`。

## 第 6 节：桥接

实现：`bridge/client.py`。构造即校验配置，连接使用 roslibpy.run(timeout=10)。
发布先规范化首尾斜杠并检查不可移除的 cmd_vel 防线，再检查 goal/cancel 白名单和消息类型。
配置将可写话题重映射为 `/cmd_vel` 或命名空间 cmd_vel 会失败。不是只依赖 YAML 中一条注释。
发布异常也释放临时 advertise，close 退订并清理连接。rosapi 查询失败返回空列表。

`bridge/offline.py` 不创建 socket，注入时钟和内存消息，执行同一套任务编排；模拟不作为 live 失败回退。
`bridge/robonix_preview.py` 与 `bridge/robonix_navigation.py` 包装固定版本官方接口。
官方 Provider 内部 ROS 话题固定，非默认话题/非 map 配置明确拒绝；连接 host/port 配置生效。

测试：`test_config.py`、`test_bridge_forbidden.py`、`test_visual_navigation.py`。

## 第 7 节：导航客户端

实现：`nav/client.py` 只编码 PoseStamped 和空 id GoalID，订阅状态和位置；不决定授权、不发布速度。
`nav/status.py` 提供 0–9 全状态名称，不再取数组最后一项当作本次结果。
dispatch 前记录旧 id，之后只绑定新 PENDING/ACTIVE id，后续只读取该 id；新任务歧义会失败。

**需求歧义处理：** “定位和里程计写同槽后到覆盖”与“优先定位”在坐标系不同时会产生错误。
`nav/pose.py` 保留 `latest` 最近有效消息槽，并分别缓存各来源；用于任务判定的 get 优先选新鲜、
同坐标系的 AMCL，再考虑同坐标系 odom。绝不将 map 与 odom 直接混合计算距离。
字段缺失/无效时保留上次有效值，但过期值不可用于执行；没有位姿不回退到 (0,0)。
这属于保守处理，不实现隐式 TF 转换。

PoseStamped 无客户端 action id，无法在其他程序并发发送目标时保证唯一归属。
本实现要求单导航客户端，漏掉接受状态会失败而不是用旧成功状态补齐证据。

测试：`test_nav.py`、`test_mission_failures.py`。

## 第 8 节：数据有效性

实现：`validation/topics.py`。默认采样 2–3 秒，统计 count/hz_est/ok；必需 scan、odom、amcl_pose，
status 可暂缺。采样结束或订阅中途失败均退订。没有增加“有消息即定位正确”的不实承诺。
编排另检查有效同坐标系位姿和时效，这是执行门，不改变健康报告“短窗口有消息”的定义。

测试：`test_validation.py`，以及每个必需话题缺失时不 prepare、不发目标的任务测试。

## 第 9 节：任务编排

实现：`mission/runner.py`。配置/授权入口检查→连接→有效位姿→预览→健康采样→静止偏移检查
→prepare→begin_confirmation→confirm→可选 dispatch→监控→日志。

- 未确认 dispatch 在连接前抛错；只确认停在 CONFIRM。
- dry-run 运行内存桥接、同一任务编排与真实 NavClient 编码，不仅打印虚构成功。
- 每次任务最多一次 publish_goal；用过的 runner 不可再次运行或从 dry-run 切到 live。
- 发布异常、定位过期、导航失败、超时、人工中断均尝试 cancel；不自动重试目标。
- SUCCEEDED 需要关联状态；保护/人工取消只有观察到 PREEMPTED/RECALLED 才记 PREEMPTED。
- 取消未证实、取消异常保持 FAILED，记录 cancel_error / cancel_terminal_observed；不写零速度。
- JSON 保存状态、健康报告、快照、失败前状态与最终状态、唯一 log_path，不保存明文令牌。

测试：`test_mission_dry_run.py`、`test_mission_failures.py`、`test_cli.py`。

## 第 10 节：视觉

路径 A：`vision/detect.py`、`vision/pipeline.py` 纯候选计算；`mission/detection.py` 在任务拿到当前
位姿后生成候选，回到同一个 MissionRunner。图像向右为负 ROS yaw；步长是启发式，不是测距。
配置里真实检测话题作为扩展点保留，当前提供 Mock 和 CLI 注入，不假称已接 YOLO。
Mock 禁止用于 live，显式 --live 的 CLI 注入由操作者负责输入观测，仍需 confirm 与 dispatch。

路径 B：`vision/targets.py`、`vision/frames.py` 识别/计算/筛选，无发布或执行接口。
`mission/visual.py` 编排官方候选→官方令牌→人工确认→执行，同时使用公共 SafetyController
复核本机距离与授权。官方令牌只交给官方 execute；本机令牌不能代替官方令牌。
预览不可用、目标重复/丢失、方向变化、过期等失败不回退路径 A。
所有同标签二维码在检测层保留；需要一个方向的编排层遇到多个时拒绝，不随机选择。
绘图仅注释图像，结果含 preview_only/navigation_goal_sent，输出明确区分模拟与实车。

测试：`test_vision_mapping.py`、`test_qr_filter.py`、原二维码/官方适配测试。

## 与实车验收的区别

这些测试证明本机规则、消息编码和故障处理，不证明控制板固件正常、地图正确、定位误差受控或
取消后物理停止。官方同步执行的目标跟踪/看门狗依赖安装的参考 Provider；本轮只核对源码接口，
没有部署到车辆。用户反馈的“30 cm 实际约 2 cm”仍需对应实车日志和规划器参数定位。
