# 官方导航与目标检测接入

## 三个参考项目的关系

| 项目 | 本课题中的作用 |
|---|---|
| `syswonder/robonix` | 提供能力契约、Provider API、代码生成与运行工具 |
| `robonix-rosmaster-x3-safe-move` | X3 的 ROS1 导航适配：候选预览、一次性令牌、人工确认、执行监控与取消 |
| Robonix 机器人目录 | 查找机器人部署组合和来源，不是独立的目标检测程序 |

目标检测应作为前端接入：

```text
图像 → 指定目标与图像中心 → 相机标定后的目标相对方向
     → preview_move_options → 匹配服务端候选编号
     → prepare_selected_move → 人工确认
     → execute_prepared_navigation → 状态 / 取消
```

`safe_move` 不接受视觉程序随意指定坐标；执行阶段只接受 Provider 签发的令牌。
检测器应从已通过地图、定位和路径检查的候选中推荐编号。
二维检测框本身不能提供物体在地图中的坐标或米制距离。

## 无运动阶段

用户当前不能确认地图和初始位姿，部署检查不启动底盘或提交导航目标。
MakerControl 仍有自己的控制板进程；后续启动 ROS 底盘前必须安排串口交接，
不能让两套控制程序同时占用控制板。

官方 CLI 名为 `move_base`，它与 ROS 的 `move_base` 导航节点不是同一个程序。
为避免 PATH 混淆，使用完整路径：

```bash
/home/jetson/rosmaster_x3_deploy/scripts/move_base --dry-run
```

无 AMCL、costmap、`make_plan` 时，预期是报告未就绪并拒绝生成可执行任务。
这种拒绝说明保护路径运行正常，不表示小车已具备导航能力。

当前 ROS Master 监听 `127.0.0.1:11311`，rosbridge 实际监听 `0.0.0.0:9090`。
在小车终端手动检查 ROS 时，先设置：

```bash
source /opt/ros/melodic/setup.bash
export ROS_MASTER_URI=http://127.0.0.1:11311
export ROS_IP=127.0.0.1
rosnode list
```

启动脚本只请求了回环 rosbridge 地址，但这个旧版 ROS/Autobahn 实现实际绑定
所有接口；记录以 `ss` 的真实结果为准。参考 CLI 自行设置回环 ROS 环境。
当前前置检查约需 45 秒，期间小车未收到本次检查发出的目标或速度指令。
